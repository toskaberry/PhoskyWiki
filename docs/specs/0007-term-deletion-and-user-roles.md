# 词条删除入口与用户权限管理

日期：2026-09-11。状态：已确认，用户通过 implement 指令授权实施。

## 已确定的需求

- 全站软删除指定词条 `导入词条-3f5b4ed0-997e-458a-a0e9-c98bd53bf79c`，保留内容与历史供恢复。删除后，其下视角也不可公开访问。管理员仍可在回收站看到该词条。
- 管理员具有删除词条能力；个人页面提供管理员回收站入口，可查看和恢复已删除词条。
- 增设超级管理员，先授予用户自己的账号。仅超级管理员可以查看全体用户及调整用户权限。
- 超级管理员具备全部管理员能力，审核时仍算管理员，包括审核资格、审核人数统计和管理员直接编辑。
- 超级管理员可以任命其他超级管理员；任何人都不能降级自己的账号，也不能移除最后一位超级管理员。
- 本次存量清理仅针对指定词条。测试应可靠清理自己创建的内容，不按标题前缀批量清理历史数据。

## 现有实现依据

- 历史页已提供软删除，`/admin/deleted` 已提供恢复；复用现有删除与恢复机制。
- ADR-0004 规定父词条删除后隐藏子视角，不改写子视角的独立删除标记。恢复父词条不会恢复已被独立删除的视角。
- 当前个人主页没有用户列表和角色管理。多个权限入口及审核人数统计直接识别 admin，新增角色需要统一覆盖这些判断。
- 浏览器导入用例生成同格式随机标题，目前没有清理步骤；当前测试 fixture 要求 localhost 和隔离环境。标题相似不能单独证明线上词条来源。

## 实施范围

- 词条页直接提供管理员“删除词条”按钮；确认时展示词条名称及受影响视角数量。个人页面提供回收站入口，复用已有列表和恢复流程。
- 超级管理员个人页面提供用户管理区域，可查看全体用户的名称、邮箱和权限，按用户选择普通编者、管理员、超级管理员；列表支持分页和查找。
- 角色修改由服务端鉴权，并在并发修改下执行自身降级与最后一位超级管理员保护。权限变更对后续请求生效，旧会话不能继续使用已撤销的权限。
- 保留权限变更记录，包含操作者、目标账号、修改前后角色和时间。邀请、账号恢复等既有入口不能绕过超级管理员的权限边界。
- 审核仍沿用现有票数和提交时快照规则。超级管理员按一名管理员计数，一次批准算一票。
- 使用隔离环境验证完整操作流程；测试清理按本次创建对象的准确身份执行，在断言失败时也尝试清理并报告清理失败。进程意外中止的残留交由隔离测试环境重置处理。
- 实施后核对线上指定词条的真实页面 ID、完整标题与关联视角，再执行软删除并验证公开列表、详情和搜索不可见。标题内 UUID 不是页面 ID。
- 初次提权只针对用户明确指认的账号，核对后执行；不根据种子管理员配置或显示名称猜测。

## 验收重点

1. 普通编者无法删除、恢复词条或管理用户权限；管理员可删除和恢复，不能调整用户权限；超级管理员具备全部上述能力。
2. 删除词条后公开入口及关联视角不可访问，恢复后可见性遵循原有独立删除规则，历史保留。
3. 超级管理员可以任命和调整其他用户；自身降级、越权调用、并发导致的最后一位超级管理员丢失均被拒绝。
4. 超级管理员可审核、直接编辑，并计入审核人数；普通编者原有审核规则保持成立。
5. 测试成功和断言失败后均清理自己创建的内容，其他正常内容不受影响。

## 运维执行

首次超级管理员授予使用受控维护命令 `ops:production promote-first-superadmin --target host:port/database/user --environment production --user-id ID --name NAME`。命令要求账号名称唯一、名称和 ID 均准确匹配既有管理员；已有超级管理员时由站内用户管理完成后续任命。同一账号重复执行不产生重复提权记录。具体账号信息在受保护的运维环境核对，不写入本规格。

角色调整同时撤销目标账号尚未消费的恢复令牌及其此前签发的邀请/恢复资格，防止旧令牌取得新权限。普通管理员不能为超级管理员签发密码恢复资格。运维管理员恢复入口兼容超级管理员，恢复密码不改变角色。
